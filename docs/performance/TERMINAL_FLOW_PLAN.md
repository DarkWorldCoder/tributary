# Terminal output ownership: implementation and remaining checks

Source review and implementation checked 4 November 2026. The desktop transport contract below is implemented and covered by the [verification record](terminal-flow-verification.json). Remaining native/platform and working-set measurements are listed below; this is not a total application RAM result.

The previous path coalesced PTY text into 8 ms/64 Ki-character batches and immediately forwarded every batch to `term.write`. It had no parser acknowledgment or producer backpressure, and an explicit flush could leave an earlier timer scheduled. Desktop terminals now use `core/terminal-output.js` and the renderer consumer helper for acknowledged delivery. Legacy direct clients retain the event-based contract; their coalescing flush now also clears its existing timer.

The [official xterm flow-control guide](https://xtermjs.org/docs/guides/flowcontrol/) recommends write callbacks and high/low watermarks rather than pausing on every small chunk. The installed xterm typings confirm that the write callback runs after parsing; installed node-pty exposes `pause()` and `resume()`. The guide's historical internal buffer-limit example must not be assumed to describe the installed xterm version.

Implemented contract:

- Register a renderer consumer before releasing initial output, so the shell prompt is not lost during asynchronous terminal creation.
- Give each mounted consumer an opaque lease. Sequence acknowledgments must match that lease and cannot release future or already-released frames. Replacing a consumer invalidates late callbacks from the old one.
- Retain only a bounded transport window and unavoidable already-delivered native read overshoot. Stop the PTY at a high watermark and resume below a low watermark. Specify whether accounting uses UTF-16 code units or encoded bytes; never equate either with total process RAM. Keep all output in order while the terminal remains open.
- Acknowledge after xterm parses a frame, not when IPC receives it. Hidden mounted terminals must continue parsing; an overwhelmed or disconnected consumer must apply backpressure rather than grow an unbounded JS/IPC queue. Coalesce acknowledgments to avoid one RPC per character or native chunk.
- Natural process exit must deliver queued output before the exit marker. Explicitly closing a terminal may discard its remaining display output and must dispose queue state, timers, subscriptions and the child. Concurrent close calls must remain safe.
- Renderer replacement needs an explicit adoption/reattachment contract for existing native terminals. Paused orphan producers must not remain inaccessible forever. Preserve user-running background work; do not silently kill it merely because a panel is hidden.
- Existing native CLI and non-renderer TerminalManager clients need a defined compatible consumption mode. Desktop IPC sender validation remains in force.

Verification must cover slow/missing consumers, stale and duplicated acknowledgments, pause/resume hysteresis, initial attachment, Unicode, close during writes, natural exit with outstanding output, renderer replacement and repeated terminal lifetimes. A real PTY stress test must verify exact output/count or checksum parity, a bounded observed in-flight window, and responsive interrupt input under fast output. Native renderer/total-process measurements are separate from deterministic queue counters. Stopped preview metadata, preview iframes and visited xterm scrollback remain separate retention owners.

Recorded native observations: the largest outstanding window was 131,072 UTF-16 code units, and the largest retained transport window was 181,589 units with a largest observed read of 65,536 units. The latter stayed within the configured window plus one observed native read. On interruption the transport drained to zero; hiding the panel retained its consumer, and reloading recovered the same terminal ID/shell PID with a new consumer token. Both the disposable shell and flood producer were verified absent at cleanup. The full suite passed 465 tests; type checking and the production UI build passed.

A replacement renderer recovers the PTY and unacknowledged transport frames; previously parsed scrollback, names and terminal editor state are not durably reconstructed. Output may slow when a hidden/background renderer parses slowly. The high/low and packet limits account for transport text/metadata, not native kernel queues, GPU resources or total process RAM. Retained string backing allocations are not inferred from character counts. Aggregate budgeting across many active terminals, visited scrollback/GPU lifetimes, packaged builds and macOS/Windows native runs remain unfinished. No before/after whole-app RAM or input-latency distribution is claimed.
